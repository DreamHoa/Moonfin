## PGS 字幕

### 2026-11-18 回退恢复与按索引绘制

旧版在某个 PGS 字幕块耗尽 Range 请求重试后会继续处理后续块。回退落在同一个解码器的缓冲范围内时，原先的重启条件只检查缓冲起点，跳过的块因此留在时间线缺口里。对样本 C 的 `39:10.306–39:13.434` 字幕模拟三次临时失败后，旧版回退约 30 秒，播放经过该区间时仍未重新请求该块。

修复集中在 [`mkvPgsSource.js`](../packages/app/src/utils/mkvPgsSource.js) 和 [`pgsRenderer.js`](../packages/app/src/utils/pgsRenderer.js)。对仍有时间余量的字幕块，用剩余显示时间限制额外的一次请求。对已跳过的块记录缺口，回退到缺口内或之前时创建新解码流并重新读取。MKV 索引给出当前有效的显示集时间戳，已解析的画面可立即绘制，进入后续未解析的显示集时按索引清屏。

| 受控场景 | 实机结果 |
| --- | --- |
| 前三次读取失败，第四次恢复 | 首遍在 `39:10.684` 绘出目标字幕，回退约 30 秒后在 `39:10.346` 再次绘出。 |
| 四次读取均失败，随后恢复请求 | 首遍缺失，回退约 60 秒后新建解码器并重新取数，在 `39:10.652` 绘出。 |
| 正常网络下回退约 30 秒或 60 秒 | 原版也曾两次正常显示。这些对照帮助区分临时读取失败与回退本身的影响。 |

上表时间为 AVPlay 视频时钟的观测值。故障注入验证了可重复的软件缺陷，首次用户报告发生时的网络状态缺少同步日志。提前预读和额外推迟视频跳转的试验已撤回，跳转回调内暂停视频停留在草案。保留的改动覆盖读取预算、缺口恢复与索引绘制。

## BU8000 界面性能

专用构建去掉书籍和漫画、Watch Parties 与 SyncPlay、Seerr；音乐、直播、预告片和主题仍可用。焦点与滚动竞争、重复布局、过大的海报请求、详情页多余请求和设置预览重复渲染已分别处理。

| 同设备对照 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 首页目标影片行就绪 | 12.2 秒 | 9.1–9.5 秒 |
| 首次详情可操作 | 7.85 秒 | 1.38–1.52 秒 |
| 无新增请求时，14 次横向移动的最长 RAF 间隔 | 220 ms | 75 ms |
| 同一横向场景的主线程长任务累计 | 653 ms | 245 ms |

前两行来自 UI 加载对照，后两行来自随后的渲染对照，各自有独立基线。影片详情接口触发的服务器、代理和网络合计等待约 0.41–0.45 秒。冷海报加载、纵向滚动、详情返回和首次打开设置仍有本机开销。详细方法和其他指标见 [构建性能记录](../BU8000-performance.txt) 和 [渲染审计](../BU8000-rendering-audit.txt)。

## 其他会话中可复用的结论

- Litefin 已暂停，Moonfin 是当前播放器主线。可复用的是测量方法和 Range 缓存定位。Litefin 遇到的显示缩放裁切和播放状态问题归该客户端，后续针对 Moonfin 时需另行复现。
- Windows 对照播放器可用于确认同一轨道在另一解码链路上可见；对照时固定片源、轨道和视频时间。HDR 对照还需区分片源码流和播放器输出目标。
- TV Home、电视系统组件清理、防固件更新和 HDMI ARC 设置有各自的边界。桌面启动、遥测或固件维护的结果归设备侧，播放器问题以 Moonfin 的实机数据单独验收。
