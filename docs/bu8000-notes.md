# Moonfin BU8000 注意事项与验收方法

当前版本、实机结论和未完成事项见 [项目进度](bu8000-progress.md)。这里记录复测时需要固定的条件，以及数据足以支持哪些结论。

## 构建、部署和收尾

在 Moonfin 仓库根目录运行以下检查和构建。已安装 Tizen CLI 时可按常规方式构建，使用独立签名工具时可通过下面的命令生成未签名 WGT。

```bash
npm install
npm test --workspace packages/app -- --runInBand --watch=false
npm run build:bu8000 -- --skip-tizen-cli
```

- 确认工作分支、提交和构建标记。保留此前验收过的回退包，使用同一应用身份和作者签名原位安装，以保留本地设置和登录。核对电视端与 WGT 中的 JS/CSS 哈希，再把测试结果归到这一构建。
- 临时调试尽量只覆盖本次会话。结束时退出调试启动、关闭临时 SDB 通道，普通启动 Moonfin 并回读状态。安装、签名和资源核对分别记录，其后的播放与字幕验收也各有结果。
- 电视接口同时超时时，先确认待机状态和连接，已授权时尝试 Wake-on-LAN。恢复后用电源状态和启动标识判断是否发生重启。需要重启整台电视时单独取得明确授权。观察设备状态以后台读回为主，有必要时再截图，操作后给画面充分时间稳定。

## 先定位字幕失败的环节

1. 固定影片版本、字幕轨和目标时间段。记录 `PlaybackInfo` 的播放方式、容器、编解码器、轨道索引与内嵌顺序，以及 AVPlay 的真实播放时钟。内嵌与外挂描述字幕的存放位置；SRT/SubRip、ASS/SSA 和 PGS 描述字幕格式。`Forced` 轨道标记也需要结合具体时间段的实际字幕包判断。
2. 从同一 MKV 核对目标字幕包。字幕提取接口返回 404 时，记录该请求的状态和片源能力，再查看 MKV 中是否存在有效字幕数据。AVPlay 有时只暴露部分文本轨道，原生映射需要足够的轨道信息。选轨时保留物理字幕轨序列。
3. 分别记录 Range 请求和响应体完成、PGS 显示集解析、时间戳被选中、Canvas 首次出现对应非透明像素的时间。出现空白时，检查目标显示集及其清屏边界。看到前一句留下的像素时，应继续核对实际绘制时间戳。
4. 跳转后回读视频实际落点。AVPlay 在这个样本上会按关键帧落地，请求回退秒数、真正倒回的距离和字幕预读等待分别记录。从目标前约 30 秒或 60 秒连续播过目标片段，用实机表现检验恢复。
5. 做受控故障对照时，只对目标字幕块模拟临时失败。分别验证有时间预算时首遍恢复、耗尽预算时首遍缺失，以及恢复请求后回退重播。结束调试时移除临时探针，保留脱敏后的时间线和结果。

### PGS 实现中需要保留的约束

- 对内嵌 MKV 的 Range 取数保留 `no-store`、响应体截止时间和有限重试。按字幕时间顺序交付显示集，避免为一个持久失败的块挂住整个解码流。
- 区分不可变索引和当前游标。索引复用限于对应片源、字幕轨和播放生命周期。跳转后重新建立正确的上下文，Normal composition 可能需要前序调色板、窗口和位图定义。
- 失败时记录缺口，回退经过缺口时重建只能按序追加的解码流。用 MKV 索引确定应显示或清除的时间戳。libpgs 的流解析仍需要向后窥读，后续显示集的预读也要保留。
- 首页、播放方式或字幕轨改变时检查旧任务清理，尤其是切轨、关闭字幕、回退重建和离开播放器。移除旧 Canvas 内容可以避免残留字幕造成假阳性。
- 普通播放已通过的样本仍需覆盖。改动涉及选轨、HTML 渲染或回退时，一并测试原生轨道映射、有限字幕格式以及缺少 Web Streams 时的兼容路径。

## 后台批量验证与实机验收口径

- 用已认证的客户端请求 `PlaybackInfo`，依据媒体源返回的内嵌 PGS 元数据定位轨道。按 MKV 索引发有限范围请求，收齐字幕块后，用电视上同一构建的 libpgs 和离屏 Canvas 批量解码、绘制。这个流程可在 AVPlay 保持 `NONE` 时完成。
- 对照索引和解析的时间戳及顺序，统计非空显示集、实际出图、缺失和清屏残留。已知漏句用固定时间戳复测。PGS 显示集数量包含清屏与动画更新，统计时保留这一单位。
- 实速验收采集目标时间窗、实际落点和出图时的播放时钟。逐条离屏验收覆盖取数、解码、绘制与清屏，实时连续播放另行覆盖网络和调度。AVPlay 视频平面可能与应用合成层分开，截图可用于确认字幕层；报告需注明截图覆盖的图层。
- SRT/SubRip 单独测首次切轨和连续显示，ASS/SSA 单独测轨道与样式。外置 SRT 可以给兼容 SDR 和有声倍速提供简单的起点，内嵌 PGS 的画面验收仍用原轨。

## 性能、HDR 和音频的验证边界

- 性能记录同时写请求耗时、长任务和 RAF 间隔。无新增网络请求的同场景 A/B 可以定位本机焦点和滚动负载。区分冷启动、暖缓存和图片解码条件，RAF 指标用于比较调度，面板刷新率和遥控输入延迟需要独立测量。诊断脚本入口为 [`scripts/profile-ui.cjs`](../scripts/profile-ui.cjs)。
- 保留实际选中的媒体源、请求的源和会话正在播放的源三个字段的核对。返回详情时第一版被选中，属于详情页状态问题；播放会话则以实际源和播放器状态为准。
- HDR 对照使用同一文件、画面模式和时间点，分别检查码流、直放状态、电视伽马和实际显示。`ST.2084` 确认 PQ 模式。HDR10+ 的动态元数据、色调映射和高光表现按各自的证据验收。Emby 的 HDR/SDR 标签适合作为排查线索，最终对照使用实际码流和电视状态。
- 在 BU8000 接 Sony HT-S20R 的已讨论方案中，HDMI ARC、Anynet+、接收器 HDMI 输出和数字输出自动构成电视端基线，eARC 设为关闭。AC3 5.1 用实际片源和音响端输出确认，倍速、有声和环绕声保持分别验证。
- Litefin、TV Home、电视系统清理和固件维护各有独立记录。跨客户端可共用对照流程，相同结论需在目标客户端复测。桌面启动或系统组件状态优先通过设备侧记录定位。

## 发布前脱敏

- 公开文档保留通用机型、软件版本、实验条件、匿名样本、字幕时间戳和聚合结果。私有样本映射、对白和截图原件留在本地。用占位符代替实际域名、内网地址、端口组合和文件路径。
- 从提交中剔除凭据、令牌、会话和用户 ID、媒体源 ID、序列号、MAC、DUID、签名证书和私钥。单独检查 HTTP 请求头、查询参数、重定向 `Location`、调试地址和截图元数据，令牌可能出现在多处。
- 从提交中剔除原始日志、HAR、抓包、设备备份、字幕提取文件和安装包。发布复现记录时，优先提供匿名化的播放方式、状态码、请求计数、时间窗以及绘制和清屏结果。提交前检查 diff 和引用路径。
